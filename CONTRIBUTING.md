# Contributing to Angels of Anonymity Website

Thank you for your interest in contributing to our project! Here's how you can help.

## Code of Conduct

- Be respectful and professional
- Provide constructive feedback
- Help maintain a positive environment

## How to Contribute

### 1. Reporting Issues
- Check existing issues first
- Provide clear description
- Include steps to reproduce
- Add screenshots if relevant

### 2. Suggesting Enhancements
- Check if already suggested
- Describe the enhancement clearly
- Explain the use case
- Provide examples if possible

### 3. Submitting Changes

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature-name`
3. Make your changes
4. Test thoroughly
5. Commit with clear messages: `git commit -m "feat: add your feature"`
6. Push to branch: `git push origin feature/your-feature-name`
7. Submit a Pull Request

## Coding Standards

### HTML
- Use semantic HTML5 elements
- Keep accessibility in mind
- Maintain proper structure

### CSS
- Follow the existing style structure
- Use CSS variables for consistency
- Keep responsive design principles
- Comment complex styles

### JavaScript
- Use vanilla JavaScript (no frameworks in core)
- Follow existing naming conventions
- Add comments for complex logic
- Test in multiple browsers

### File Organization
```
Keep all related files together
Use clear, descriptive names
Follow existing directory structure
```

## Commit Messages

Use conventional commits:
```
feat: add new feature
fix: fix a bug
docs: update documentation
style: update styling
refactor: refactor code
test: add tests
chore: maintenance tasks
```

## Testing

Before submitting:
- [ ] Test on desktop browsers (Chrome, Firefox, Safari, Edge)
- [ ] Test on mobile devices
- [ ] Test keyboard navigation
- [ ] Check responsiveness
- [ ] Verify animations work smoothly
- [ ] Check accessibility

## Pull Request Process

1. Update documentation as needed
2. Test all changes thoroughly
3. Provide clear PR description
4. Link related issues
5. Request review from maintainers
6. Address feedback promptly

## Content Updates

### Adding New Projects
1. Prepare high-quality image (1200x800px recommended)
2. Update `js/data.js` with project details
3. Ensure all technologies are listed
4. Test project modal display
5. Submit PR with changes

### Updating Team Information
1. Get approval from team member
2. Prepare professional photo if needed
3. Update `js/data.js` and social links
4. Test team card display
5. Submit PR

### Adding Competitions
1. Gather competition details
2. Prepare images (competition logo, team photo, certificate if available)
3. Update `js/data.js` with competition information
4. Add description and achievements
5. Test display in competitions section

## Performance Guidelines

- Keep file sizes minimal
- Optimize images (use WebP/AVIF with fallbacks)
- Avoid unnecessary animations
- Minimize CSS and JavaScript
- Test Lighthouse scores (target 90+)

## Documentation

- Keep README.md updated
- Document new features
- Add inline code comments where needed
- Update CHANGELOG if applicable

## Questions?

- Create an issue with your question
- Contact the team at contact@angelsofanonymity.com
- Check existing documentation

## Recognition

Contributors will be recognized in:
- CONTRIBUTORS.md file
- GitHub contributors section
- Website credits (for major contributions)

Thank you for helping make Angels of Anonymity better! ✦
